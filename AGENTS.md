## Imported Claude Cowork project instructions

## Render notes (for Claude sessions)
- Site: Quarto 1.10.18 since 2026-10-01 (was 1.9.38; `quarto render`; install in a fresh container with the `quarto-1.10.18-linux-amd64.deb` from the quarto-cli GitHub releases — quarto.org itself is blocked by the egress proxy). Quarto cannot run on the mounted folder inside the device shell (sqlite "disk I/O error", temp dirs cannot be removed) — render in the cloud container instead: stage `_quarto.yml`, `_header.html`, `_footer.html`, `styles.css`, `pic.png` and the `.qmd` files, run `quarto render`, then commit back only the changed `.html`, `search.json` and `sitemap.xml`. Unchanged pages reproduce byte-for-byte. Caveat: `extension*.qmd` set an og:image, and Quarto writes the image's width/height meta tags only if the PNG is present — stage `accweb-map.png`/`accweb-map-zh.png` too, or do not commit `extension*.html` (those tags would be dropped).
- Bootstrap CSS hash: with Quarto 1.10.18 the container compiles the theme to `site_libs/bootstrap/bootstrap-bb5ce4f09c3d713477d34b1921f208f7.min.css` while the Mac build produces `bootstrap-445b8638c3d06994fee0907d791121c4.min.css` (same rules, different order; under 1.9.38 the pair was `4694…` vs `1580…`). The Mac file is already in `site_libs/`, so after a container render `sed` the hash in every `.html` back to the Mac one (`445b…`) before committing, and never commit `site_libs/`. Verified 2026-10-03: after that sed, unchanged pages are byte-identical to the Mac build. `sitemap.xml` lastmod = the source `.qmd` mtime, so hand-edit the changed pages' entries in the Mac sitemap instead of committing the container one (staged files carry the staging time). pCloud sometimes leaves `search.json` on disk padded with trailing NUL bytes — a fresh render fixes it. Also verified 2026-09-06: the CV `.Rmd` files render fine in the container (R + rmarkdown + texlive-lang-chinese, GenWanMin2TW-R/-SB in /usr/local/share/fonts, microtype line neutralised) for layout checks — but keep the Mac PDFs as the published ones.
- CV: sources live in the sibling repo `../yyliou/cv/*.Rmd` (8 variants) and are built with `Rscript render.R` (rmarkdown → xelatex, template `jenpan-latex-cv.tex`). Needs R + rmarkdown + xeCJK (texlive-lang-chinese) + TeX Gyre Pagella + the 源雲明體月 (GenWanMin2TW) fonts from `fonts/`. R is not installed on the device shell either — render the CVs in the cloud container too: `apt-get install -y r-base-core r-cran-rmarkdown texlive-lang-chinese pandoc`, copy `fonts/GenWanMin2TW-*.otf` into `/usr/local/share/fonts/` and run `fc-cache -f` (family name 源雲明體月), then stage the 8 `.Rmd` + `render.R` + `jenpan-latex-cv.tex` and run `Rscript render.R`. The container build is NOT identical to the Mac build: the Mac runs TeX Live 2026 (xdvipdfmx 20260317) and has no microtype, the container has TL 2023 (xdvipdfmx 20220710) with microtype installed. Rendering an unchanged .Rmd in the container and comparing page images against the Mac PDF shows (a) microtype protrusion shifting Latin line breaks — fixable by neutralising the `\IfFileExists{microtype.sty}` line in a container-only copy of `jenpan-latex-cv.tex`, after which the English CV matches — and (b) xeCJK punctuation spacing that still differs on every page carrying Chinese text, which TL 2023 cannot reproduce (CTAN/TinyTeX downloads are blocked by the egress proxy). Page counts and content do match. Also install only GenWanMin2TW-R and -SB in the container (NOT -M), or fontconfig picks M as the CJK bold and the headings come out lighter than the Mac's SB. So: edit the .Rmd here, but let the user run `Rscript render.R` on the Mac for the PDFs — macOS Terminal/RStudio can only be granted click-only computer-use access, so the render cannot be driven from a session. Paper titles appear in both the site (`research*.qmd`) and all 8 CV files — change all of them together.
- CV zh right-hand years: the 4 Chinese CVs define `\hfillbreak` (= `\hfill\penalty0\mbox{}\nobreak\hfill`) in `header-includes`. Use `\hfillbreak \mbox{114 年}` instead of `\hfill \mbox{114 年}` on an award/experience line whose name is too long for one line — the year then drops to the next line but stays flush right (plain `\hfill` puts it flush LEFT on the next line, which the user rejected 2026-09-06; used for the 系友會 scholarship). Container preview render without R: `LC_ALL=C.UTF-8 pandoc x.Rmd --to latex --from markdown+autolink_bare_uris+tex_math_single_backslash --template <template copy with the microtype line removed> -V "CJKoptions=BoldFont={源雲明體月 SB}, BoldItalicFont={源雲明體月 SB}" -o x.tex` then `xelatex` ×3 (fonts in `~/.fonts`, `fc-cache -f`); text diff vs the Mac PDF then differs only in xeCJK punctuation spacing (one project-title line break), so still keep the Mac PDFs.
- Fonts: after any text change run `python3 subset_fonts.py` on the device (`pip install --user brotli` first; fontTools is already there). Since 2026-10-10 the site uses two weights only, R (400) and SB (600); `font-weight: 500` was folded into 600 in `styles.css` (headings, `.paper-title`, `.site-footer-name`), so do not reintroduce 500 for MyFont text. Each weight's main layer is split: `fonts/GenWanMin2TW-<w>-core.woff2` (Latin, punctuation, symbols, plus the Chinese characters the English home page shows) and `fonts/GenWanMin2TW-<w>-cjk<n>.woff2` (the other site characters, 60 per file, grouped by the pages that show them), so English pages download only the two core files (~108 KB) and Chinese pages only the shards they need. The script rewrites the generated @font-face block at the top of `styles.css` (never hand-edit that block; URLs carry a content hash, every rule has `font-display: swap`). It deletes main-layer files it no longer produces, but the device shell cannot delete, so it prints them instead: move those to `_to_delete/`. `python3 subset_fonts.py --check` must then say the main layer covers every character. `fonts/fallback/` holds every Big5 character and the font's symbols in 512-code-point blocks (R and SB only), and browsers fetch a block only for a character the main layer lacks, so a missed rebuild shows no 缺字 but costs an extra ~170 KB per block. `--fallback` regenerates the blocks (about 3 min on the device; output is byte-identical unless the script changes). The sibling `../yyliou` repo no longer has HTML viewer pages, so the script reads only this repo.
- Images: the about pages show `pic.webp` (same 728 px portrait with transparency, 33 KB); `pic.png` stays only as the site-wide og:image. The extension pages show 1600 px JPEG copies (`accweb-*.jpg`), while their front matter keeps `image: accweb-map(-zh).png` + `image-alt` so og:image and its width/height tags stay on the PNG.
- Research statement (`../yyliou/rs/rs*.Rmd`, rmarkdown's default template) in the container: also `apt-get install lmodern texlive-latex-recommended texlive-latex-extra`, and run `Rscript render.R` under `LC_ALL=C.UTF-8` (otherwise the R-computed date in rs_zh comes out as `115 <U+5E74> 10 <U+6708>`; use it for the CVs too). The default template loads microtype whenever it exists and the Mac has none, so rename `/usr/share/texlive/texmf-dist/tex/latex/microtype/microtype.sty` during the rs render and restore it afterwards. Checked 2026-10-08: built this way (CV template with the microtype line neutralised), the English CVs match the Mac PDFs line for line and the Chinese ones differ only in xeCJK spacing (e.g. the teaching-evaluation table columns); the container PDFs were written back as the published ones because the user asked for a render.
- Git on the mounted folder: use `git --no-optional-locks status`; plain `git status` leaves a `.git/index.lock` that cannot be deleted from the device shell (move it to `_to_delete/` if it happens).
- Research statement bold name: `../yyliou/rs/bold-me.lua` (loaded via `pandoc_args` in both rs Rmd files) runs citeproc itself, bolds "Yu-You Liou" inside the refs div, then unwraps the citations and drops the bibliography metadata so rmarkdown's later --citeproc has nothing to redo (added 2026-10-08).
