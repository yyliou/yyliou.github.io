Also verified 2026-09-06: the CV `.Rmd` files render fine in the container (R + rmarkdown + texlive-lang-chinese, GenWanMin2TW-R/-SB in /usr/local/share/fonts, microtype line neutralised) for layout checks — but keep the Mac PDFs as the published ones.

The container build is NOT identical to the Mac build: the Mac runs TeX Live 2026 (xdvipdfmx 20260317) and has no microtype, the container has TL 2023 (xdvipdfmx 20220710) with microtype installed. So: edit the .Rmd here, but let the user run `Rscript render.R` on the Mac for the PDFs — macOS Terminal/RStudio can only be granted click-only computer-use access, so the render cannot be driven from a session. - Fonts: after any text change run `python3 subset_fonts.py` on the device (`pip install --user brotli` first; fontTools is already there. On 2026-11-06 the device shell's home disk was full and `pip install --user` failed with "No space left on device"; installing to /tmp worked: `TMPDIR=/tmp pip install --no-cache-dir --target /tmp/pylib brotli`, then run the script with `PYTHONPATH=/tmp/pylib`). Since 2026-10-10 the site uses two weights only, R (400) and SB (600); `font-weight: 500` was folded into 600 in `styles.css` (headings, `.site-footer-name`; `.paper-title` was later set to 400 at the user's request, 2026-10-10 — paper/project/course titles are not bold), so do not reintroduce 500 for MyFont text. Each weight's main layer is split: `fonts/GenWanMin2TW-<w>-core.woff2` (Latin, punctuation, symbols, plus the Chinese characters the English home page shows) and `fonts/GenWanMin2TW-<w>-cjk<n>.woff2` (the other site characters, 60 per file, grouped by the pages that show them), so English pages download only the two core files (~108 KB) and Chinese pages only the shards they need. The script rewrites the generated @font-face block at the top of `styles.css` (never hand-edit that block; URLs carry a content hash, every rule has `font-display: swap`). It deletes main-layer files it no longer produces, but the device shell cannot delete, so it prints them instead: move those to `_to_delete/`. `python3 subset_fonts.py --check` must then say the main layer covers every character. `fonts/fallback/` holds every Big5 character and the font's symbols in 512-code-point blocks (R and SB only), and browsers fetch a block only for a character the main layer lacks, so a missed rebuild shows no 缺字 but costs an extra ~170 KB per block. `--fallback` regenerates the blocks (about 3 min on the device; output is byte-identical unless the script changes). The sibling `../yyliou` repo no longer has HTML viewer pages, so the script reads only this repo.
